# مشروع: خدمة إعدادي (PWA) — الحالة الحالية v9.8

(كان اسمه "لوحة المتميزين". اسم التطبيق للمخدوم دلوقتي **خدمة إعدادي**، وسطر "كنيسة العذراء مريم المطرانية أبوقرقاص" فضل زي ما هو.)

## ١) نبذة

تطبيق PWA يشتغل أوفلاين، مربوط بـSupabase، لإدارة امتحانات قراءة الأسفار لمرحلة إعدادي (~٣٠ مخدوم)، مع وحدات شخصية للمخدوم (أجبية، قداسات، اعتراف)، ولوحة تميز للخادم، ولوحة مالك، ورسائل، وحضور، وافتقاد.

- الاستضافة: Netlify للاختبار (sweet-liger-f6bd22)، GitHub Pages لاحقاً.
- Supabase: مشروع الاختبار `lawha-test`.
- حساب المالك: owner@test.com (واحد فقط، مفيش super-owner).
- الواجهة عربي RTL، خط Tajawal، خلفية #08090B، ذهبي #E8C468، وضع فاتح/داكن.
- **التصميم ما بيتلمسش** (نفس الألوان والخطوط من v8.4).

## ٢) القرارات المعتمدة

| البند | القرار |
|---|---|
| الاستضافة | Netlify (اختبار)، GitHub Pages (لاحقاً) |
| PWA | قابل للتثبيت، أوفلاين، الـService Worker بيحدّث بتغيير `VERSION` في `sw.js` |
| التخزين | IndexedDB محلياً (kv + outbox) + Supabase للسيرفر |
| الأدوار | مخدوم (anonymous auth) / خادم / كاهن مسؤول / مالك (email+password؛ الدور من `app_metadata.role` في الـJWT) |
| دخول المخدوم | اسمه + كود الاسترجاع، بدون إيميل ولا كلمة سر |
| دخول الطاقم | بريد إلكتروني حقيقي + كلمة سر (مفيش اسم مستخدم) |
| كود الاسترجاع | يتولّد تلقائياً على جهاز المخدوم (٨ أحرف للجدد، ٦ للقدام). المالك يقدر يولّد كود جديد (زر 🔄) |
| الوحدات الشخصية | محلية فقط (الأجبية، الاعتراف، القداسات). **ولا دور يشوفها** |
| رفع أسفار JSON | المالك فقط |
| الحذف | ناعم ٣٠ يوم (يدوي بزر تنظيف). حذف نهائي بعد ٣٠ يوم أو بتأكيد مزدوج |
| الأرشفة | الخريجون (الثالث الإعدادي) بيتأرشفوا مش بيتمسحوا |
| إعادة الامتحان | أول محاولة هي المعتمدة (كل المحاولات تتسجّل) |
| المرحلة العمرية | إعدادي فقط |
| الحماية الحقيقية | RLS + triggers + دوال في السيرفر. الواجهة للعرض بس |
| ملفات التسليم | PWA_vX.zip كامل + مجلد/ملف الملفات المتغيرة + SETUP-vX.md + SQL مقسّم لقطع صغيرة (المستخدم على الموبايل). كل ملف يتعدّل ← رقم النسخة في اسم الملف يزيد |
| الإشعارات | صندوق رسائل داخل التطبيق + polling (بدون Push حقيقي حالياً) |

## ٣) البنية التقنية

- **Frontend**: Vanilla JS (ES modules) بدون مكتبات، وحدات تتحمّل ديناميكياً من `modules/registry.json` حسب الدور، راوتر بالـhash (`#/id`).
- **التخزين المحلي**: `js/db.js` (IndexedDB: مخزن `kv` ومخزن `outbox` لطابور المزامنة).
- **المزامنة**: `js/sync.js` REST فقط (بدون supabase-js)، إعادة محاولة بتأخير متزايد، تشتغل لما `lawha:queued` أو online أو كل دقيقتين، ومهام idempotent.
- **الدور**: `kv.staff` (من الـJWT: `app_metadata.role`)، غيابه = مخدوم. الدور بيتجدّد مع الـJWT (حتى ساعة).
- **Service Worker (`sw.js`)**: كاش للملفات، `VERSION` لازم يتغيّر مع كل تسليم. فيه شريط ذهبي "تحديث" في `index.html`.
- **Supabase**: جداول + RLS + triggers + دوال + views، و٣ Edge Functions.

### v9.6 — الترقية والافتقاد والحضور وحسابات الطاقم والنسخة الاحتياطية
- **الأرشفة**: عمود `profiles.archived_at`. المؤرشف مستبعد من سياسات الطاقم و`results_first_staff` والرسائل، وبيشوفه المالك فقط. فلتر "مؤرشف" وزر "إلغاء الأرشفة". الأرشفة للمالك فقط (في `profiles_guard`).
- **ترقية الصفوف** (`promote_grades(label, force)`، للمالك فقط): الأول←الثاني، الثاني←الثالث، الثالث←مؤرشف. مرة لكل "سنة دراسية" (جدول `app_meta`)، تأكيد بكتابة "ترقية" + تحذير لو مفيش نسخة احتياطية آخر ٧ أيام، وتتسجّل في التدقيق.
- **🤝 الافتقاد** (`followup_staff` view + `followups` جدول): قائمة مخدومين محتاجين اتصال (مش بيدخل/غاب مرتين+ في ٣٠ يوم/مش بيحل امتحانات)، فلاتر الصف والمدة، واتساب (المخدوم وولي الأمر) بنص قابل للتعديل، اتصال، "✓ تم الافتقاد" بملاحظة، إخفاء اللي اتفتقد آخر ٧ أيام.
- **🗓️ الحضور** (`meetings` + `attendance`): تسجيل اجتماع لكل (تاريخ + صف)، حاضر/غائب/بعذر، "الكل حاضر"، تعديل اجتماع سابق، تقرير نسبة الحضور (٣٠/٩٠/الكل). الغياب بيغذّي الافتقاد.
- **👥 حسابات الطاقم** (`modules/owner/staff.js` + Edge Function **`staff-admin`**): list/create/set_role/set_active. المالك فقط، ما بتلمسش المالك ولا نفسك ولا حسابات بلا دور، الأدوار خادم/كاهن فقط، الإيقاف بـban، وتسجيل في `audit_log`.
- **🧰 أدوات المالك** (`modules/owner/tools.js`): نسخة احتياطية كاملة JSON (١٤ جدول) + CSV المخدومين + CSV النتائج (BOM للعربي) + تنبيه لو آخر نسخة أقدم من ٣٠ يوم، وواجهة الترقية.
- `js/sapi.js`: مساعدات مشتركة لوحدات الطاقم (REST، تنسيق، أخطاء، روابط واتساب).

1. `schema.sql` لحد v9.6 (أو القطع في SETUP-v9.2 ثم v9.5 ثم v9.6).
2. Edge Functions: `restore` (موجودة)، `reset-password`، `staff-admin` — **Verify JWT = OFF** للتلاتة، و`ALLOWED_ORIGIN` Secret.
3. حساب الكاهن: يتنشئ من Dashboard ثم `update auth.users set raw_app_meta_data = … '{"role":"priest"}'`.
4. نشر `PWA_v9.6` على Netlify.

## ٩) المتبقي والمقترحات

**اقتراحات اتعرضت ولسه ما اتنفذتش:**
1. **خصوصية البيانات**: الخادم دلوقتي يشوف تليفونات المخدوم وولي أمره (وقائمة الافتقاد بتعرضها). الاقتراح: الأرقام للكاهن/المالك فقط أو لصف الخادم نفسه (تعديل RLS + views + واجهة). **أهم نقطة متبقية.**
2. **تحليل الأسئلة**: أكتر أسئلة بيغلط فيها المخدومين (محتاج تخزين إجابة كل سؤال).
3. **Push حقيقي** للرسائل (VAPID + Edge Function + اشتراكات؛ iOS محتاج تثبيت التطبيق 16.4+).

**أعمال ناقصة/تحسينات محتملة:**
- أداة **استعادة** من النسخة الاحتياطية (النسخة بتتنزّل بس، والاستعادة يدوية).
- نقل من `lawha-test` لمشروع إنتاج + GitHub Pages، وتحديث `js/config.js`.
- عرض حضور المخدوم لنفسه (حالياً للطاقم بس)، وتصدير تقرير الحضور CSV.
- تحديث صف المخدوم المحلي بعد الترقية (الصف المعروض في صفحته قد يفضل القديم؛ الرسائل بتتبعت صح من السيرفر).
- ضوضاء في سجل التدقيق بعد الترقية (سطر لكل مخدوم + سطر ملخّص).
- تنظيف: `ROLE_LABEL` في `auth.js` غير مستخدم، ملفات SETUP القديمة.
- تغيير دور حساب بيسري خلال ساعة (تجديد الـJWT).

**تحذيرات مهمة:**
- كل قطع SQL والـEdge Functions **ما اتجرّبتش فعلياً** بعد v9. أي خطأ يتبعت وأصلحه.
- الترقية والحذف النهائي عمليات لا رجعة فيها: خد نسخة احتياطية قبلهم وجرّبهم على بيانات تجريبية.
- الـpolling (رسائل المخدوم/طلبات المالك) بيشتغل والتطبيق ظاهر على الشاشة بس.
