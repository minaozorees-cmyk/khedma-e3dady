# SETUP-v8.1 — لوحة التميز المباشرة (المرحلة ٧)

## الملفات المتغيّرة عن v7
| الملف | التغيير |
|---|---|
| `supabase/schema.sql` | إصلاح `profiles_cap` + `profiles_select_own` + view جديد `results_first_staff` |
| `pages/servant.html` | تبويب "📡 نتائج مباشرة" + بوابة الدور + تصدير CSV/Excel/PDF/نسخ |
| `js/sync.js` | `resultsFirst()` + مسح كاش النتائج عند خروج الخادم/المالك |
| `sw.js` | `VERSION='v8'` فقط (عشان الأجهزة تحمّل الملفات الجديدة) |

باقي الملفات كما هي في v7.

## ما تغيّر في v8.1 عن v8
- `sw.js`: `VERSION='v8.1'` (يجبر الأجهزة على تحميل الملفات الجديدة).
- `servant.html`: عمود/فلتر السفر بالعنوان (`title`) مع fallback لـ`book_id`؛ البوابة تفحص `exp` (بهامش ٦٠ ثانية) وتجرّب تجديداً واحداً قبل القفل؛ تعليق `<!-- lawha v8.1 -->` في أول `<head>` للتأكد من النسخة.
- `sync.js`: `title` ضمن الأعمدة المطلوبة من الـ view. `schema.sql`: الـ view فيه `title` (left join مع `books`).

## الخطوات
1. **Supabase → SQL Editor:** شغّل `supabase/schema.sql` كاملاً (آمن لإعادة التشغيل: كله `create or replace` / `drop ... if exists`).
2. ارفع الملفات لـ GitHub Pages. الأجهزة هتاخد v8 عند فتح التطبيق مرتين (أو زر التحديث لو موجود).
3. **اختبار سريع (٥ دقايق):**
   - **الإصلاح:** مخدوم تجريبي يعمل ٣ ملفات، تحذف واحد من الجدول (`update profiles set deleted_at=now() where id=...`)، ويقدر يعمل رابع. وبعد الحذف الملف المحذوف ميظهرش له.
   - **الـ view كخادم:** سجّل دخول بحساب خادم، افتح `servant.html` ← "📡 نتائج مباشرة" ← لازم تظهر الأسماء والصفوف وأول محاولة وعدد المحاولات.
   - **عمود `title`:** في "📡 نتائج مباشرة" عمود/فلتر السفر لازم يعرض اسم السفر بالعربي (مثلاً يهوديت) وليس `book_id` (judith). نفس الشيء في ملفات CSV وExcel المصدّرة. لو ظهر `book_id` فمعناه إن السفر مش موجود في جدول `books` (الـ view بيرجع للـ `book_id` في الحالة دي).
   - **الـ view كمخدوم:** من الـ SQL Editor أو بتوكن مخدوم: `select * from results_first_staff` لازم يرجّع صفر صفوف (مش صفوفه هو).
   - **أوفلاين:** افتح التبويب مرة أونلاين، اقفل النت، أعد فتحه ← لازم تظهر "🟠 نسخة محفوظة من …".
   - **البوابة وانتهاء الجلسة:** من DevTools → Application → IndexedDB → `lawha` → `kv` → `staff` غيّر `exp` لرقم قديم، ثم افتح الصفحة أونلاين ← لازم تتجدد وتفتح. أوفلاين ← "لا يوجد اتصال". ولو الـ refresh token مرفوض ← "انتهت الجلسة" مع زر "خروج وإعادة دخول".
   - **البوابة:** افتح رابط `pages/servant.html` من متصفح/جهاز مخدوم (أو بدون دخول) ← لازم تظهر "غير مصرّح".

## ملاحظات مهمة
- **البوابة واجهة فقط (UI gate).** ملف `servant.html` نفسه علني على GitHub Pages ومينفعش يتخبّى. اللي بيحمي البيانات فعلاً هو RLS + شرط `my_role()` داخل الـ view: من غير JWT خادم/مالك السيرفر مش هيرجّع أي نتيجة.
- البوابة تجدّد التوكن تلقائياً مرة واحدة لو انتهى (بدون loop)، فالخادم مش بيتقفل عليه كل ساعة.
- البوابة بتقرأ جلسة الخادم من IndexedDB بنفس الـ origin، فلو فتحت `servant.html` محلياً من `file://` هتظهر "غير مصرّح". لتعطيلها في الحالة دي غيّر `window.__GATE=true` إلى `false` في أول الملف.
- **كاش النتائج** (`kv.resultsBoard`) فيه أسماء وصفوف مخدومين على جهاز الخادم؛ بيتمسح تلقائياً عند "خروج (خادم/المالك)".
- **الـ RSA** وتبويباته المحلية (فك الكود، لوحة المتميزين) لم تتغيّر، وتفضل احتياطي.
- أسماء الأسفار بتظهر بـ `book_id` زي ما هو في الجدول.
- الحد الأقصى للقراءة ٢٠٬٠٠٠ صف (pages × ١٠٠٠)؛ لو اتعدّى هيظهر تنبيه "مقصوص". Keyset pagination لسه TODO.
- التصدير (CSV/Excel/PDF/نسخ) للخادم والمالك بنفس الصلاحية، وبيطبّق الفلاتر الحالية. خلايا CSV/Excel اللي تبدأ بـ `= + - @` بتتحصّن ضد formula injection.
- PDF محتاج `lib/html2canvas.min.js` و`lib/jspdf.umd.min.js` (زي ما في v7).

## لم يُنفَّذ في v8
- إمكانيات المالك الإضافية (حذف/تعديل مخدوم من اللوحة): مؤجلة لخطة ٨ب (الحذف الناعم + التنظيف بعد ٣٠ يوم). سياسة `profiles_owner_all` جاهزة في السيرفر.
- `schema.sql` والـ view لم تُختبر على Supabase حقيقي (غير متاح هنا). منطق JS الصافي (تجميع، فلترة، CSV/Excel، escaping) اختُبر بـ Node.
